## Known Issue: Ring Buffer Reuse in test_w4_perf_p2
All four mmul() calls in test_w4_perf_p2 write ring index 0, set HTAIL=1, and wait for NHEAD=1.
After P09 completes, NHEAD stays at 1. P10/P11/P12 find NHEAD already 1 and exit in 2 cycles,
re-reading P09's stale output. P09 is the ONLY test that actually executes the MXU.
This is a PRE-EXISTING test harness design issue (present in both pre-fix and post-fix code).

## Causal Evidence

### Evidence Item 1: Pre-fix → Zero Output
With row-major activation data (committed code), the MXU preload sequencer produces
ALL ZEROS at the SRAM output area (0x20018000). All four AXI beats are 0x0.
cos_sim = 0.0 against all golden values. The MXU compute pipeline never activates.

### Evidence Item 2: Post-fix → Non-Zero Output
With tile-major activation data (working tree), the MXU produces non-zero output
at the SRAM output area. The SRAM_WR AXI beats show actual INT32 values being written.
cos_sim = 0.564 against P09 golden — a PARTIAL PASS (in [0.5, 0.999) range).

### Evidence Item 3: DMA Works
Post-fix P09 DRAM readback (180c0000980b0000) matches SRAM output (180c0000980b0000),
confirming the DMA output store path is functional.

### Evidence Item 4: The Fix Matters
The ONLY code change between before/after runs is in sim/perf_tests.py:
  - Before: act.tobytes(), wp.tobytes()
  - After:  pack_int8_activation_tile_major(), pack_int4_tile_major()

This single change transforms PERF output from all-zeros to non-zero INT32 values.
This proves the data-layout hypothesis: MXU preload sequencer expects K-vector
tile-major layout; row-major data causes complete compute failure.

### Evidence Item 5: Incomplete Fix
cos_sim = 0.564 (P09) is < 0.999 threshold. Additional issues may exist:
  - Weight scale format may not match firmware expectation
  - pack_int4_tile_major may not correctly handle INT4-packed byte layout
  - Firmware descriptor size fields may need adjustment for tile-major sizes
  - These are separate issues from the activation layout problem

## Ring Buffer Issue
P10,P11,P12 read stale P09 output because all mmul() calls reuse ring index 0 and
HTAIL=1 without incrementing. This is a pre-existing test harness design issue
in test_w4_perf_p2() — NOT caused by the tile-major packing change.
To get a clean PERF-11 measurement, an isolated single-test run is needed.
