Constraint method (low-regression-risk, per todo 19):
  1. Policy: REJECT, not wrap. dispatch_cmd() in firmware/npu_firmware.c
     validates every descriptor address range before issuing any
     transaction. An out-of-window DRAM range marks the command failed
     (status=1, completion error, LAST_STATUS marker 0x000070xx).
     Wrapping was deliberately avoided: it would silently alias two
     distinct buffers into the same physical window (adversarial-QA
     'address wrap aliasing' probe — answered by choosing reject).
  2. Window: DRAM_BASE=0x80000000, DRAM_SIZE=0x00800000 (8 MB),
     DRAM_END=0x80800000 (was 0x0FF00000, an unused documentary macro).
     dram_range_ok(addr,size) passes addresses below DRAM_BASE
     (SRAM/MMIO/ROM are not DRAM) and rejects DRAM ranges outside
     [DRAM_BASE, DRAM_END).
  3. Coverage: command desc_addr + MMUL input/weight/output/scale +
     SFU input/output + ROPE input/output + Vector a/b/o + DMA_COPY
     src/dst + PCIe_DMA axi (sizes match the exact byte counts the
     firmware transfers, incl. SFU/Vector scratch rounding).
  4. Test configs: NOT modified. Audit of the FM-SOC RTL builders
     (sim/rtl_soc_runner.py) shows every case already stays inside the
     8 MB window (max P4 result end 0x8075_8000; wgt_dram 0x80200000;
     descriptors 0x80000080-0x80001000). The firmware now enforces the
     window, so future test configs that escape it fail loudly instead
     of triggering backdoor/DRAM errors (the BUG-RTL-SOC-002 symptom).
     dram_model.v untouched (16 MB RTL array, 8 MB harness backdoor cap
     unchanged — no RTL recompilation risk).
