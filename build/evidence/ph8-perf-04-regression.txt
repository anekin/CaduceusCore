ROOT CAUSE ANALYSIS:
1. Primary: MXU computation produces wrong results through firmware doorbell path.
   The tile-major packing (pack_int8_activation_tile_major, pack_int4_tile_major)
   is verified correct for individual bytes. The firmware's offset calculations
   (act_offset = k_start * 64, wgt_offset = (n_tile * num_blocks + k_block) * 2048)
   are tile-major compatible. The wrapper preload constants (ACT_BEATS_PER_K=64,
   WEIGHT_BEATS_PER_K=32) match tile-major sizes exactly.

   Suspected issue: The MMIO address conflict — firmware sets mxu->I_ADDR/W_ADDR/O_ADDR
   to wrapper-loaded SRAM addresses, but the wrapper's broadcast bus uses internal
   buffers, not these MMIO registers. This may cause address misrouting during
   multi-K-tile accumulation.

2. Secondary: Doorbell protocol bug — sequential mmul() calls within same test
   write HTAIL=1 repeatedly without advancing. After first MMUL, NPU_HEAD=1,
   so second HTAIL=1 write is a no-op. Fix: advance HTAIL (1→2→...) or reset
   NPU_HEAD between calls.

PERF-11: STILL NOT RESOLVED. The tile-major fix in PR.mmul() is correct for

needed into mxu_start() MMIO vs wrapper address configuration conflict.
