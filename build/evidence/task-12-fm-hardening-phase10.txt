## What was implemented
Doorbell/bridge-path MMUL with the PERF-13 attn_weight shape (sim/perf_tests.py:255):
  - M=32, K=32, N=64 issued via host_write_command(OpCode.MMUL) + firmware
    run_loop — NOT the spike_host forward path (which never emits an
    attn_weight GEMM, the structural FM blind spot for BUG-RTL-SOC-007).
  - Deliberately N=64 (not N=128): todo 6/7 are load-bearing on N=128 for
    weight-tile alignment, so this test pins the K<64 / N=64 single-tile
    shape they do not cover.
  - Deterministic random INT8 activations/weights with fixed seed
    RandomState(20260812); activations packed with
    cocotb_bridge.pack_int8_activation_tile_major, weights with
    GoldenMXU.pack_int4.
  - Scale buffer in the FM bridge-reader layout: num_blocks=ceil(K/128)=1,
    [1][64] fp32 contiguous (mmio_bridge.py:248-252). Non-trivial random
    scales in [0.5, 1.5). For N<=TILE_W the firmware's tile DMA
    (tile_scheduler.py:137, tile_width*4 bytes) coincides with the bridge
    layout, so both readers see the same buffer.
  - Asserts: command completes with status='done'; output matches
    GoldenMXU.matmul_int4_per_block(group_size=128) within
    rtol=1e-5, atol=1e-5; anti-vacuous golden non-triviality gate.
  - Failure injection: monkeypatches miniv.NPUFirmware._dispatch so the
    descriptor is never dispatched and no completion status is written
    (status 'unknown', output DRAM untouched). Asserts the happy-path
    gates then fail: status != 'done' AND zero output != golden.
