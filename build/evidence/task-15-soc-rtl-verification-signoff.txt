## Root causes found and fixed during this task (sim/rtl_soc_runner.py only)

1. Per-op cycle measurement is NOT available via NPU_HEAD polling: the
   firmware drain loop only writes NPU_DB->NPU_HEAD once per batch
   (npu_firmware.c:678), so the head register jumps 0 -> 26 in one step.
   Switched to the DRAM completion ring (comp[0]=cmd_id per command).
2. The DRAM completion status word is unrecoverable: dram_model.v writes the
   whole 512-bit word per beat ignoring s_axi_wstrb, and the firmware's
   narrow 32-bit stores land with data replicated across word lanes — the
   comp[1]=status word is clobbered/relocated. Execution correctness is
   therefore gated by the per-op output comparison (stronger: a dropped op
   leaves its zeroed output buffer → cos_sim gate fails).
3. `_build_block` VRESID golden bug (pre-existing, first golden-vs-RTL
   exposure): the builder stored the residual `a` as FP16 while the RTL
   resid_add consumes raw INT32 lanes (vector_top does no fp16→int32
   conversion). Fixed: store the truncated INT32 residual — same conversion
   GoldenVector.residual_add applies internally. FM-SOC-032/-032-CORRUPT are
   fingerprint/hash based (format-independent) so their verdicts are
   unaffected; todo 16 re-runs them.
