## What was implemented
Doorbell-path MMUL accumulate regression (CTRL[2]=1 on the second K-block
command of one descriptor chain):
  - One MMUL descriptor with M=1, K=256, N=128 -> tile_scheduler.tile_mmul
    chains TWO MXU commands (K=128 each) to the same SRAM output
    accumulator; the second command carries CTRL[2]=1 accumulate
    (tile_scheduler.py:148, npu_firmware.c:541).
  - mmio_bridge.py:268-278 accumulate semantics asserted explicitly:
      final output == partial0 + partial1
    where each partial is GoldenMXU.matmul_int4_per_block(group_size=128)
    computed on its own K-slice (0:128 and 128:256) — the "golden built by
    combining matmul_int4_per_block partials" per plan C3.
  - Output also asserted equal to the full-K matmul_int4_per_block golden,
    and an anti-vacuous gate asserts the first partial is non-trivial and
    that the output is NOT just the second partial.
  - Orthogonal to todo 6: scales are all-ones here (todo 6 covers non-trivial
    scale VALUES); what is under test is the accumulation between the two
    commands. Distinct DRAM addresses from the todo 6 tests.
  - Failure-injection variant monkeypatches MMIOBridge._run_mxu_compute to
    force accumulate=False while firmware still sets CTRL[2]=1; asserts the
    output then equals ONLY the second partial (and != accumulated golden),
    proving the happy-path assertion would catch a CTRL[2]-ignored
    regression.
