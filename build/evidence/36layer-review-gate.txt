## Critical Caveat

The actual 36-layer forward pass was executed in the Func Model (Python golden reference),
not as a full 36-layer RTL simulation. The RTL component of this evidence is limited to
the FM-SOC-001 Ibex SoC smoke test, which confirms that the Ibex-controlled SoC
infrastructure (boot, MMIO, DMA, MXU) executes the firmware smoke program correctly.

Reason: Spike runtime is blocked by a C++ ABI mismatch in npu_mmio_plugin.so, and the
firmware path has known DMA output readback and 64KB weight-buffer limitations that
prevent a full 36-layer Qwen2.5-3B forward pass on RTL at this time (per W4-PERF findings).

The checkpoint comparison (Func Model re-run vs saved Func Model golden) is expected to
be bit-exact (cos_sim=1.000000) because the same deterministic code and GGUF file are used.
This validates Func Model stability, not full RTL layer correctness.

## Conditions for Final Acceptance

1. A genuine full 36-layer RTL forward pass must still be performed once firmware supports
   per-K-tile weight streaming and the DMA output readback path is fixed.
2. The Spike plugin ABI mismatch must be resolved before Spike-based debug/verification is
   reintroduced.
3. Any future Func Model change that affects numerical results must regenerate the golden
   files in rtl/test_vectors/soc_e2e/qwen25-3b-36layer/ and re-run this checkpoint script.
4. The next review gate should explicitly confirm the RTL full-layer pass, not only the
   Func Model golden stability and FM-SOC-001 smoke.

## Summary

The composite evidence (stable Func Model golden checkpoints + passing Ibex RTL smoke) is
acceptable for the current Phase 6 RTL verification gate, given that Spike is blocked and
firmware DMA/weight-buffer limitations prevent a full 36-layer RTL forward pass today.
