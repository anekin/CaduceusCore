Problems & Solutions

Problem: DMA CH1 readback zeros

Wave 1

PERF path could not read MXU output back from DRAM.

Solution

Compared FM-SOC vs PERF CH0/CH1 register values and DRAM snapshots. Root cause was firmware output DMA row interleave, already fixed by 7aec7a3. No bridge change needed.

Problem: PERF-06 M=32 cos_sim 0.05

Wave 2

M=32 matrix multiplication failed while M=1 was closer to passing.

Solution

Signal probes ruled out RTL accumulator reset. A mini-model falsified the firmware offset formula. Fixed act_offset = k_start * TILE_H and corrected output row interleave.

Problem: Ibex segment run NaN/INT_MIN

Wave 3 / ISSUE-13B

First completed segment run ended with ladder FAIL and NaN outputs.

Solution

Two independent bugs: activation buffer was row-major instead of column-major broadcast layout, and MXU store-out ignored per-block FP32 scales. Fixed controller/wrapper and Python layout alignment.

Problem: L19 corruption after boundary

Wave 3 / ISSUE-13C

L19 standalone passed but failed when chained after L9→L10.

Solution

Full-DRAM preload was not enough; 4 MB SRAM scratch and wrapper staging held stale state. Zeroed SRAM at every segment boundary.

Problem: DESC_BASE ring overlap

Wave 3 / ISSUE-13D

L19/L20 still corrupted after SRAM fix.

Solution

Descriptors (64 B) collided with command-ring entries (32 B) at offset ≥128. Moved DESC_BASE from 0x80001000 to 0x80010000.

Lessons Learned

Compare paths, not blocks

When two flows share the same RTL but behave differently, capture their register configurations and data snapshots before blaming the controller.

One failure can hide multiple bugs

PERF-06 needed both the tile-major offset fix and the output row-interleave fix. Re-run cleanly after each change.

Long-run corruption is state, not logic

If a layer passes standalone but fails chained, audit SRAM, wrapper staging, and address-space layout before re-running hours of simulation.

Layout is a correctness contract

Func Model did not catch DESC_BASE overlap because it lacks an address-space layer. Add an AddressSpaceContract check and ring-stress regression.

Make long runs observable

The 94-minute silent run was killed because no progress file existed. Flush progress lines and save incremental checkpoints.

Calibrate constants, not derived metrics

FM-3 overlap is computed from mxu.double_buffer, broadcast_sync, etc. Adjust those, not a non-existent stored ratio.

Gates should fail honestly

F1–F4 each failed once for real reasons. Updating the gates made the signoff trustworthy.

Probes vs hardware-expected output

L0L19 intermediates looked wrong until compared against dequantized hardware-expected values with correct layout and dtype.

Long-Run RTL Debug Methodology

  1. Reproduce — one minimal command, one exact commit.
  2. Probe — add read-only instrumentation before editing logic.
  3. Falsify — run a mini-model or isolated case against each hypothesis.
  4. Fix — edit the smallest layer (firmware > test > RTL).
  5. Causal gate — re-run the failing case and one neighbor.
  6. Full regression — run the relevant regression surface.
  7. Independent QA — reproduce key evidence from a clean state.
  8. Document — evidence file, bug ledger entry, notepad note.

Pre-long-run checklist

  • Ring / descriptor / completion / data regions do not overlap.
  • SRAM budget confirmed for the largest layer shape.
  • Progress logging flushed to file every ~10%.
  • Incremental checkpoint saves enabled.
  • Smallest representative case runs end-to-end first.
  • No conflicting simv process on the target host.
