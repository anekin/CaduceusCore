      wire wdt_trip  = wdt_fire && !wdt_ax_hs;
      sticky set   -> `else if (wdt_trip)`
      PL recovery  -> `end else if (wdt_trip && pl_axi_wait) begin`
      SO recovery  -> `end else if (wdt_trip && so_axi_wait) begin`
      header boundary (i) now quotes `wdt_trip && so_axi_wait`
    CHOICE + REASON (as required by the plan): implemented, not deferred as a residual, because
      (a) the hazard is real and cheap to close: on the trip cycle the recovery branch outranks the
          FSM case, so a completed AR/AW handshake would be discarded (slave already accepted the
          burst) and a mid-row W beat would truncate the burst without WLAST;
      (b) the gate cannot disarm the watchdog: wdt_cnt saturates at WDT_TIMEOUT-1 and is only cleared
          by leaving the AXI-wait states, so wdt_fire stays high and wdt_trip is re-evaluated on the
          very next cycle that has no handshake — the worst case is a one-cycle deferral;
      (c) it is inert for every covered path: the WDT case's dead slave drives all readys to 0, so no
          handshake ever completes and the trip cycle is unchanged.
    FULL-GATE vs AR/AW-ONLY: all four channel handshakes are included (R/W beats too, not only the
      AR/AW examples named in F2-4) because the two named hazards cover only half the damage: an
      accepted R beat mid-burst would leave the slave's remaining beats to be consumed by an
      unrelated later read, and a completed non-final W beat is exactly the "burst without WLAST"
      case. A beat handshake is progress by definition of the counter (it advances pl_beat_cnt /
      so_w_beat / so_scale_beat or completes the row).
    X NOTE (recorded, not a claim): an X on a slave-side ready/valid makes wdt_ax_hs X -> not-true in
      the `if`, i.e. an unknown slave suppresses the trip for that cycle. Every wrapper TB and the
      FM-SOC AXI RAM drive these to known values; no `COCOTB_RESOLVE_X` was used or added.
    COVERAGE BOUNDARY (honest): no test completes a handshake on the trip cycle, so the gate's
      deferral branch is NOT positively exercised — it is justified statically (b,c) and by the
