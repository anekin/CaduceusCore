5. INLINE OVERLAP AUDIT (op05 stray-write domain)
--------------------------------------------------------------------------------
Method: inline `python3 - <<'PY'` (no permanent script file created).
Rules (documented per plan Momus-A2):
- MMUL output_size_bytes = M * N * 4 (output_elem_bytes == 4 for all MMULs)
- non-MMUL output_size_bytes = elements * output_elem_bytes
- DRAM address = SRAM_BASE (0x20000000, cocotb_bridge.py:114) + manifest
  sram_output_addr offset.

Audit script source:

```python
import json
SRAM_BASE = 0x20000000  # cocotb_bridge.py:114
with open('rtl/test_vectors/qwen_blk0/blk0_manifest.json') as f:
    m = json.load(f)
ops = m['ops']
rows = []
for op in ops:
    name, opcode, dims = op['name'], op['opcode'], op['dimensions'] or {}
    elem_bytes = op.get('output_elem_bytes', 4)
    out_off = int(op['sram_output_addr'], 16)
    out_base = SRAM_BASE + out_off
    if opcode == 'MMUL':
        M, N = dims.get('M', 1), dims.get('N', 1)
        size = M * N * 4
        rule = f"M={M}*N={N}*4"
    else:
        elems = dims.get('elements', dims.get('q_len', 0) + dims.get('k_len', 0))
        size = elems * elem_bytes
        rule = f"elements={elems}*{elem_bytes}"
    rows.append((name, opcode, out_base, size, rule))
print("== 17-op declared OUTPUT interval table ==")
for i, (name, opcode, base, size, rule) in enumerate(rows):
    print(f"{i:>3} {name:<20} 0x{base:08X} {size:>8} [0x{base:08X}, 0x{base+size:08X}) {rule}")
op05 = ops[5]
op05_base = SRAM_BASE + int(op05['sram_output_addr'], 16)
op05_declared = 32 * 2 * 4
op05_fp = 32 * 256
print("manifest out_addr (SRAM-relative): 0x%06X" % int(op05['sram_output_addr'], 16))
print("computed DRAM base: 0x%08X" % op05_base)
print("declared dense output: %d B" % op05_declared)
print("actual write footprint: %d B" % op05_fp)
print("overshoot: %d B = 248 B/row * 32 rows" % (op05_fp - op05_declared))
fp_lo, fp_hi = op05_base, op05_base + op05_fp
hits = []
for i, (name, opcode, base, size, rule) in enumerate(rows):
    if i == 5:
        continue
    lo, hi = base, base + size
    if lo < fp_hi and fp_lo < hi:
        hits.append((name, max(lo, fp_lo), min(hi, fp_hi)))
if hits:
    for name, lo, hi in hits:
        print("OVERLAP-HAZARD: %s overlaps op05 @ [0x%08X, 0x%08X)" % (name, lo, hi))
else:
    print("OVERLAP-HAZARD: none")
```

Characterization (not a third hypothesis — downstream consequence of the
same root cause, per plan Oracle-R4-A4): all 11 overlapping ops share the
same SRAM output region 0x020000 (sram_layout output_buffer scratch).
Access is strictly sequential — each op's run_step overwrites the scratch
region before the next op consumes it, so op05's 8KB stray write only
clobbers bytes of the shared scratch region that are re-written later, never
a foreign live tensor. This benign scratch reuse explains why the 16 other
ops pass while op05 fails. Most significant neighbour: op07 attn_weight
MMUL (M=32) is programmed with the same padded-DIM1 store-out model and
uses the identical 0x020000 output base — the same root-cause family, same
scratch region, hence also benign by overwrite.
