1. INSTRUMENT AUDIT (sim/verification framework)
═══════════════════════════════════════════════════════════════════════════

H0-INSTRUMENT: fm_adapter-python
  Primary instrument: FuncModelAdapter(firmware_mode="python") — NPUFirmware (miniv)
  emulator + FuncModel + MMIOBridge, driven through the shared DUTAdapter action
  surface (Action.sram_preload / mmio_write / poll_status / sram_readback).

Audit findings (file:line citations):
(a) Dual firmware modes CONFIRMED: fm_adapter.py:54-79 — "python" (miniv.NPUFirmware)
    and "spike" (real firmware compiled to npu_firmware_spike.elf; FuncModel
    use_spike=True). Spike artifacts PRESENT on this host (spike_src/build +
    firmware/build/npu_firmware_spike.elf; spike_firmware._is_spike_available()=True),
    so fm_adapter-spike is runnable in principle. However, spike mode runs the REAL
    firmware dispatch loop — that is MODE-B (firmware-ring-chain) semantics, NOT the
    MODE-ORIG per-op-preload flow. For the H0 replay of MODE-A the python mode is the
    faithful instrument; spike mode is recorded as available-but-not-applicable.
(b) 17-op descriptor-stream dispatch via mmio_bridge._run_mxu_compute: NOT a direct
    adapter action. The FM bridge exposes it ONLY through the frontdoor MMIO path —
    writing MXU.CMD with START bit triggers _run_mxu_compute synchronously
    (mmio_bridge.py:136-174). There is no Action type that maps to a descriptor/
    ring command (doorbell Action maps to FuncModel.host_write_command, the
    firmware-ring flow). This is CONSISTENT with todo 1: MODE-ORIG=per-op-preload
    never uses descriptors — firmware resident/idle, Python MMIO direct drive
    (cocotb_bridge.py:5261-5283, 0 doorbell/ring hits). Descriptor dispatch is
    therefore n/a for the per-op H0 replay (and for H0's firmware-scheduling
    discriminative power, see matrix).
(c) Backdoor observation tagging AVAILABLE: sram_readback/dram_readback/mmio_readback
    classified allowed_obs_backdoor (scenario.py:176-186, operation_classifier),
    registered in _backdoor_classification, evidence_metadata carries
    action_counts + backdoor_classification + firmware_mode + abi_version
    (fm_adapter.py:688-744). RTLAdapter mirrors the same contract
    (rtl_adapter.py:52+, cocotb/VCS-bound — not runnable on sz0002).
(d) Instrument gaps found while building the replay (transport-level only; the
    logical op stream and all data are unchanged):
    GAP-1 VRESID operand width: FM MMIOBridge VECTOR op=5 reads operand A as FP16
        (dim*2 bytes, mmio_bridge.py:563-565) and fp16->int32 converts inside
        GoldenVector.residual_add. RTL loads BOTH operands as INT32
        (vector_soc_wrapper.v valid_bytes_total_rd = wrp_len_eff*4) and
        resid_add.v adds raw INT32 lanes; ABI: "RESID_ADD — Saturating INT32
        residual add". The 3-layer golden is a+b (INT32; verified element-wise).
        Replay computes INT64-add-with-INT32-clip (resid_add.v semantics) and
        matched=int64-add on all 6 VRESID ops. => the FM bridge op5 fp16 path is
        a STALE pre-ABI semantic (cross-ref: rtl_soc_runner.py:3058-3060 stages
        the residual pre-converted to INT32 for exactly this reason).
    GAP-2 ROPE DIM encoding: RTL per-op driver writes DIM[15:0]=element PAIRS
        (elements//2); RTL SFU wrapper consumes pairs (sfu_soc_wrapper.v:167
        "one pair (x,y) per dim"). ABI (spec/npu_abi.json SFU DIM) and firmware
        (npu_firmware.c:664) pack ELEMENTS; FM bridge follows the ABI. Replay
        writes DIM=(head_dim<<16)|elements — same logical op, canonical FM encoding.
    GAP-3 partial-N weight staging: RTL driver stages 64-col-padded tile-major
        (pack_int4_tile_major); FM bridge contract is dense row-major (K*N/2 bytes).
        Byte-identical for all 64-wide tiles; dense used for attn_score N=16.
    GAP-4 RMSNorm norm-weight fold: generator golden = (x/rms)*gamma
        (gen_qwen25_3b_rtl_vectors.py:256-258 _rmsnorm with attn_norm_w/ffn_norm_w,
        eps=1e-6); FM bridge rmsnorm_hw has NO gamma input and eps=1e-5
        (golden_executor.py:515-532); RTL rmsnorm_hw.v has no weight port either.
        => strict compare vs manifest golden FAILS for all 6 RMSNorm ops
        (1900-2042 of 2048 elements out of tolerance; e.g. g/fm elementwise ratio
        0.33..0.63 = the model's norm weights). NOT a driver-layer fault.
(e) W1.3 SFU smoke-mode discovery (audit finding with 07-07 relevance):
    test_qwen25_3b_3layer builds SFU instructions WITHOUT golden_output
    (cocotb_bridge.py:5421-5431) -> run_step sets passed=True unconditionally
    ("smoke mode", :1807-1811). So the W1.3 per-op run — both the 07-07 original
    and today's MODE-A re-run — NEVER golden-compared any SFU op (RMSNorm/RoPE/
    softmax/SiLU). Only MMUL (fp32 cos vs expected.npz) and Vector (INT32 exact
    vs golden hex) were compared. GAP-4 therefore went unobserved on the RTL side.
    This does not change the REPRO verdict (the 07-07 failure ops were MMUL +
    VMUL, which ARE golden-compared) but it bounds what the RTL per-op evidence
    can claim about SFU.

Audit conclusion: the framework is reusable as-is for the FM side of MODE-A.
FuncModelAdapter(python) + MMIO bridge can dispatch the 17-op-class manifest
stream (all 51 ops) through the frontdoor MMIO surface (MXU via CMD.START ->
_run_mxu_compute per tile; SFU/Vector via CMD.START), with backdoor tagging.
A direct "descriptor stream" dispatch is n/a (per-op mode has none — consistent
with MODE-ORIG). Instrument verdict: fm_adapter-python (primary), fm_adapter-spike
available but semantically MODE-B, no built(bounded) needed beyond 1 helper file.

3. FIRMWARE-RESIDENT CHEAP DIFFERENTIAL (variant B)
═══════════════════════════════════════════════════════════════════════════
MODE-ORIG=per-op-preload => firmware is resident but NOT in the dispatch loop
(todo 1). H0's firmware-SCHEDULING discriminative power is therefore
n/a-firmware-not-in-loop. Cheap FM-side analogue performed anyway:
  variant A: firmware booted, resident, idle (default) -> 51/51 PASS
  variant B: firmware first DISPATCHES one real ring MMUL command
             (host_write_command + run_loop, conv2d-smoke-shaped), then the same
             51-op per-op replay.
Result (full 51-op): FM-RESIDENT-DIFF: DIFFERENT (defensive_scale=False)
  - MMUL ops that run after the firmware dispatch FAIL: e.g.
    op05 cos=0.2026 max_abs=1.7e9 | op07 cos=0.2308 max_abs=7.5e5 |
    op41 cos=0.1720 max_abs=3.4e5 | op46 cos=0.2001 max_abs=4.8e9 (A: cos=1.0)
  - Root cause PROVEN: firmware ring dispatch leaves MXU SCALE_ADDR=0x14000 in the
    bridge state (probe: before=0x0, after=0x14000). The per-op driver never
    writes SCALE_ADDR; MMIOBridge._run_mxu_compute uses raw_s>0 -> scaled FP32
    store-out path REGARDLESS of CTRL (mmio_bridge.py:247-262).
  - RTL ANALOGUE EXISTS: mxu_soc_wrapper.v:173-182 — "SCALE_ADDR != 0 => scaled
    store-out; SCALE_ADDR == 0 keeps raw-INT32 store-out", latched from the APB
    MMIO stream. Same hazard class on the RTL side for mixed firmware-then-per-op
    flows.
  - Mitigation verified: with a defensive MXU SCALE_ADDR=0 write per MMUL dispatch
    (--defensive-scale), FM-RESIDENT-DIFF: identical (51/51 both variants).
  - BUG-007 relevance: in pure MODE-A the firmware never dispatches (todo 1:
    resident/idle, 0 ring writes) => SCALE_ADDR stays 0 => this mechanism is NOT
    the 07-07 cause; it is a live cross-flow stale-state hazard (residual candidate
    #3). Not fixable in this task (no product-code edits allowed).

5. RESIDUAL CANDIDATES (all listed explicitly; carried into todo 8)
═══════════════════════════════════════════════════════════════════════════

RESIDUAL-CANDIDATES:
1. cocotb-driver back-to-back write timing — FM bridge is synchronous; inter-write
   APB timing cannot be discriminated here. RTL-only candidate (unexcluded).
2. STATUS.DONE lifecycle / stale-DONE — FM bridge sets STATUS=2 synchronously;
   cannot reproduce a stale-DONE window. RTL-only candidate (unexcluded).
3. Cross-engine / cross-flow stale-state leak — CONFIRMED instance on the FM
   instrument: MXU SCALE_ADDR survives a firmware ring dispatch and flips later
   per-op MMULs into the scaled store-out path (§3, proven + mitigation verified);
   RTL analogue exists (mxu_soc_wrapper.v:173-182). Not the 07-07 cause in pure
   MODE-A (firmware never dispatched) but a live hazard for mixed flows.
4. Crossbar fairness — not observable in the FM (functional model, no arbitration);
   RTL-only candidate (unexcluded).
5. Reconstruction uncertainty (todo 1: medium) — the exact 07-07 testcase was
   never committed (first commit 79654175 on 07-08); original 45/6 artifact
   deleted; environment drift bounded but not eliminable.
6. W1.3 SFU smoke-mode gap — per-op SFU ops (RMSNorm/RoPE/softmax/SiLU) were never
   golden-compared in ANY W1.3 run (cocotb_bridge.py:5421-5431); GAP-4 (RMSNorm
   gamma fold) would fail a strict compare. Affects evidence coverage, not the
   07-07 failure ops (MMUL/VMUL).
7. ROPE DIM encoding divergence — RTL wrapper consumes PAIRS (sfu_soc_wrapper.v:167)
   vs ABI/firmware/FM ELEMENTS; per-op driver writes pairs. Works on RTL, would
   not work on an ABI-canonical wrapper. Driver-encoding quirk (GAP-2).
8. FM-bridge VECTOR op5 stale semantics — fp16 operand-A vs RTL/ABI INT32 (GAP-1);
   the FM bridge's chain-flow VRESID path diverges from resid_add.v/ABI. Pre-existing
   FM-model gap, out of BUG-007 scope, noted for completeness.
