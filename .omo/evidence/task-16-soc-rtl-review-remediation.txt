HYPOTHESES INVESTIGATED (each with outcome)
--------------------------------------------------------------------------------
Instrumentation method: monkeypatched MMIOBridge._run_mxu_compute / .handle to
count MXU CMD STARTS and per-tile executions; allclose-hook for exact diff.
Logs: .omo/evidence/_tmp_task16_debug.log / _tmp_task16_debug3.log /

H1 — Golden (Func Model) vs firmware MMUL semantics mismatch: PARTIALLY
     CONFIRMED (secondary, comparison-level). run_one_op's golden used a
     full-K block-order reference (matmul_int4_per_block over K=1536 with 12
     fp32 block accumulations), while the firmware/bridge executes one
     64-row K-tile per MXU CMD, scaling each tile by its 128-group scale and
     fp32-accumulating across 24 K-tiles (cf6736b semantics). This is the
     ~1e-4-rel summation-order noise that made task-1a (3B) FAIL at
     9.16e-05 under rtol=1e-5 — it is NOT the 7.64e+02 cause. Fixed by
     computing the reference in firmware tile order (see FIX below).

H2 — fp32 accumulation ordering / scale application in bridge: RULED OUT.
     Bridge correctly reads per-tile scales from SCALE_ADDR (firmware
     mxu_start() writes SCALE_ADDR per K-tile with double-buffered scale
     SRAM addresses — observed 2 distinct scale addrs across 576 tiles),
     TILE_SCALE_BYTES=256 == bridge's (K/128 rounded up)*N*4=256, and the
     cross-tile fp32 accumulate (CTRL[2]=1 for k_block>0) is the documented
     hardware semantic. No defect.

H3 — Descriptor/address mis-setup for Q_proj: CONFIRMED ROOT CAUSE (primary).
     TWO defects in sim/spike_host.py run_one_op:
     (a) out_addr = 0x81000000 (16 MB into DRAM) is OUTSIDE the firmware's
         8 MB DRAM allowlist window (firmware/npu_firmware.c:16,471-490
         dram_range_ok; BUG-RTL-SOC-002 / WVR-SOC-RTL-002). The firmware
         REJECTED the MMUL descriptor (status=1, no MXU CMD ever issued):
         instrumentation showed cmd_starts=0, wrp_cmds=0, tiles_run=0, while
         the doorbell still completed (done=True). The host then read an
         all-zero output → max_diff = max|golden| = 7.6382e+02. The reported
         7.64e+02 was never a numerical mismatch — it was a phantom diff
         against zeroed memory.
     (b) The activation was written row-major (input_size = act.nbytes =
         1536), but the firmware walks activations at k_block*4096 stride
         expecting the mxu_soc_wrapper broadcast tile-major layout (ISSUE-13B
         cf6736b: 64-byte word c of each 4096-byte K-tile holds column k).
         Even with (a) fixed, the compute would have read corrupted
         activations. Fixed by packing with _pack_act_tile_major_contig().

H4 — Known quantization-path tolerance (qwen l0 hidden compare): RULED OUT
     as the 7.64e+02 cause (that family is ~1e-4 rel noise). It DID explain
     the historical near-miss FAILs (task-1a: 9.16e-05 with rtol=1e-5), now
     resolved by the H1 reference alignment instead of any tolerance change.

BONUS FINDING — run_one_op had NO `return ok`: it printed "[PASS]" then fell
off the end returning None, so the mmul_smoke summary counted every op as
FAIL regardless of the comparison outcome ("0 PASS, 1 FAIL" even when the
op-level line said PASS — observed mid-fix). Fixed with `return ok`.

FIX (confined to sim/spike_host.py, run_one_op only — NO RTL touched)
--------------------------------------------------------------------------------
1. out_addr computed to stay inside the 8 MB window:
     out_addr = (wgt_addr + len(combined_weight_blob) + 0xFFF) & ~0xFFF
   (0x80345000 for Q_proj; well inside [0x80000000, 0x80800000)).
2. Activation packed to broadcast tile-major layout and descriptor
   input_size updated:
     act_packed = _pack_act_tile_major_contig(act, M, K)
     ... input_size=act_packed.nbytes (24*4096 = 98304 for K=1536).
3. Golden reference recomputed in firmware execution order (per N-tile,
   per 64-row K-tile: int32 partial, group scale, fp32 accumulate) from the
   same reordered tiled blobs the firmware DMAs — bit-comparable with the
   bridge. No tolerance loosened (rtol=1e-5 unchanged).
4. `return ok` restored at end of run_one_op.
Comment citations follow project convention (ISSUE-13B cf6736b, ISSUE-16A,
BUG-RTL-SOC-002 / WVR-SOC-RTL-002).
