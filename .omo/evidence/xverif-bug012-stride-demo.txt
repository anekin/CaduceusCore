3. Root-cause interpretation
----------------------------
The MXU engine controller computes a 64-wide output tile because dim1_n=64.
The wrapper's store-out FSM uses the same dim1_n to compute the row stride,
so it advances SRAM addresses by 64 INT32 columns (256 B) per row.
The firmware/driver expectation for this MMUL is N=2, i.e. dense row stride
of 2 INT32 = 8 B.  The cocotb checker reads 64 contiguous bytes, so after
row 0 it finds stale zero/garbage instead of row 1, producing the 62/64
INT32 mismatch signature.

4. Fix direction (already documented in bugs-soc-rtl.md)
---------------------------------------------------------
Preferred low-risk fix: drop the driver-side pad-to-64 in cocotb_bridge.py
and program DIM1 = actual N, matching firmware semantics (firmware already
writes real N to DIM1).  xverif evidence shows DIM1=2 is sufficient.
