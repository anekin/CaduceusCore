F2-1 MEDIUM  rtl/wrapper/mxu_soc_wrapper.v:31 / :401-402 + docs/bugs/bugs-module-level.md:53-56
  Overclaim in the watchdog's no-false-trip argument: "every other state ... is progress and
  clears the counter, so a long but healthy transaction can never accumulate to the threshold".
  FALSE: the K-tile turnover inside the pre-load is wait->wait (PL_LOAD_W_R -(rlast, more
  tiles)-> PL_LOAD_W_AR -> PL_LOAD_W_R, :483-495 and :509-520) and both states are in
  pl_axi_wait (:414), so wdt_cnt accumulates continuously from the first PL_LOAD_W_AR until
  PL_READY. The counter is a PER-PHASE budget (whole pre-load; one store-out row, cleared only
  by SO_IDLE/SO_TRANSFORM), not a per-transaction-stretch budget. A legitimately slow slave
  (~244+ cycles/beat average) on a large-K pre-load can false-trip; the practical margin is the
  separately-stated 10x threshold headroom (85,536 vs 1e6) plus the empirical 25-case run, which
  do hold. Required fix: reword both sites to "cleared when both sequencers leave the AXI-wait
  states (PL_READY / SO_IDLE / SO_TRANSFORM) - once per pre-load phase and once per store-out
  row" and state the large-K exposure. No RTL change required.

F2-2 LOW  rtl/tb/apb_conformance_real_tb.sv:24, :680; docs/bugs/bugs-soc-rtl.md:907
  Mixed-revision line citations: ":128" is the BASE 8ba7af1 line of the read mux (HEAD :133);
  ":290" is a HEAD line (base :290 = `default:`); ":209" for the START self-clear is the BASE
  line (HEAD :214). Behavior described is correct in every case. Fix: cite HEAD numbers or drop.

F2-3 LOW  rtl/wrapper/mxu_soc_wrapper.v:439
  Sticky-clear `wrp_cs && pwrite && (paddr == OFF_WRP_CMD)` omits `penable` (the module's own
  wrp_trigger :210 requires it), so the flag clears in the APB setup phase and for an aborted
  write. Still "any WRP_CMD write clears" as documented, but the earliest-clear semantics are
  unstated. Fix: add `penable` or document the setup-phase clear.

F2-4 LOW  rtl/wrapper/mxu_soc_wrapper.v:455, :710
  The recovery branch outranks the FSM case, so on the exact first-trip cycle a COMPLETED
  handshake is discarded: if arvalid&&arready (or awvalid&&awready) is high that cycle the slave
  has accepted the burst, the FSM goes IDLE, rready/wvalid drop, and the abandoned burst's beats
  can later be consumed by an unrelated pre-load / leave a write burst without WLAST. Window is
  exactly one cycle and only on the fault path. Fix: gate the trip on "no handshake this cycle"
  or record it as a residual (the ledger currently calls the recovery "surgical" unconditionally).

F2-5 LOW  sim/tests/wrapper/test_mxu_wrapper.py:792

  [MXU_WRP_WDT-PROBE-UNAVAILABLE]) and no assertion depends on it, but it would swallow a real
  handle/rename error. Fix: narrow to AttributeError/ValueError.
