CRITICAL ENV FINDING — pytest 9.x segfaults on sz0001 without a shim

`import readline` SEGFAULTS (exit 139) under EVERY anaconda python on sz0001:
  - /NAS/Tools/anaconda3/bin/python (3.12.4 base)      → segfault
  - /NAS/Tools/anaconda3/envs/py3.11/bin/python        → segfault
  - /home/zhengs/venvs/fmpytest/bin/python (3.12.4)    → segfault
  - /usr/bin/python (system 2.7.5, system libreadline) → OK
Fault chain (faulthandler): segfault inside readline.cpython-312 extension
module init (`create_module`). The extension links anaconda's bundled
libreadline.so.8 + libtinfow.so.6; objdump shows those libs need only
GLIBC_2.15 (so it is NOT a simple version gate) — crash occurs in module init
itself. Root cause is an anaconda-bundled-libreadline vs sz0001 (CentOS 7)
incompatibility; NOT caused by the new venv.
pytest 9.1.1's `_pytest.capture._readline_workaround` imports readline
UNCONDITIONALLY at startup (pytest 7.4.4 had a win32-only guard) → every
pytest 9.x invocation crashed before collecting a single test.
WORKAROUND (no installs, no repo changes, ephemeral):
  /tmp/fmpytest-shim/readline.py contains:
    raise ImportError("readline import disabled by /tmp/fmpytest-shim shim: "
      "anaconda readline ext segfaults on sz0001 (pytest 9.x startup workaround)")
  and PYTHONPATH is extended to `sim:gen:/tmp/fmpytest-shim`. pytest's
  try/except ImportError then skips the workaround cleanly.
  Verified: with shim, `python -m pytest sim/tests/test_fm_abi_contract.py -q`
  → 6 passed (without shim: segfault).
MANDATORY for todo 4 policy: every FM-pytest command on sz0001 needs the shim
dir in PYTHONPATH (or a durable equivalent) or it will crash before running.
