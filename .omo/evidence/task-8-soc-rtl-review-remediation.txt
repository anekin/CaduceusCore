PER-FIX DESCRIPTION
--------------------------------------------------------------------------------
(a) dram_range_ok() whitelist semantics (npu_firmware.c ~:468)
    Legal = SRAM window [0x20000000, 0x20400000) + DRAM 8MB window
    [0x80000000, 0x80800000) (WVR-SOC-RTL-002 / BUG-RTL-SOC-002 unrelaxed:
    DRAM_SIZE stays 0x00800000UL). Boot ROM/DMEM, address holes, 0x4000_xxxx
    MMIO → return 0 → status=1. uint32 wraparound (addr+size < addr) rejected.
    The todo-5 CONTROL source pins ("addr >= DRAM_END", "size > DRAM_SIZE",
    "#define DRAM_SIZE  0x00800000UL") all preserved verbatim.

(b) Derived-size validation (MMUL) with checked arithmetic
    Reject when M/K/N imply more bytes than declared input_size/weight_size/
    output_size: derived_input = M*K (INT8), derived_weight = K*N/2 (INT4
    packed), derived_output = M*N*4 (INT32). Dims are bounded to ≤0xFFFF
    first (hardware masks DIM0/DIM1 to 16 bits, so larger dims are corrupted
    descriptors). Overflow-safe: dims ≤ 0xFFFF → M*K, K*N, M*N ≤ 0xFFFE0001
    (fits uint32); M*N*4 guarded by an explicit m_x_n > 0x3FFFFFFF check.
    SFU/Vector/DMA: scratch sizes now computed through checked wrappers
    (sfu_scratch_size_checked / vector_scratch_size_checked — overflow →
    status=1); DMA_COPY/PCIe_DMA rely on the range check which now includes
    the addr+size wraparound guard.
    CHECKED-ARITHMETIC NOTE: all dispatch-decision arithmetic is shift/add
    form (umul16 shift-add multiply, explicit if/return branches, volatile
    local for the accept return) — NOT compiler `mul`/`sltu`.  RISCVMini
    (the FM harness executing this hex) decodes RV32M mul as sub and does
    not decode sltu/sltiu, and GCC -O2 folds `if (cond) return 0; return 1;`
    into a bare sltu; both were verified by objdump to appear 0 times in
    dram_range_ok / write_completion / umul16 / checked-scratch helpers and
    in the dispatch derived-check region. This makes the FM runtime behave
    exactly like real RV32IM for these decisions.

(c) Completion mirror clamp (write_completion, npu_firmware.c ~:440)
    MMIO mirror index clamped to min(cmd_id, 15) — COMPLETION_STATUS is a
    16-entry array (npu-regmap.h doorbell offset 0x14); an unclamped
    cmd_id=1019 would land at 0x4000_6000+ (INTC APB window). The DRAM
    completion ring (COMPLETION_RING_ADDR + cmd_id*32) keeps the FULL 1024
    records keyed by cmd_id, unclamped. NOT clamped to 1019 (that would
    still let indices 16..1018 escape the declared [16] array).
    Compiles to bltu+li (objdump-verified, no sltu).

IRQ/WFI preservation: the drain-loop doorbell IRQ ACK (INTC.ACK = 1<<8) is
now issued BEFORE the NPU_HEAD/HOST_HEAD mirrors instead of after. This is
semantically neutral for the ABI (the ACK's job is quiescing the wakeup IRQ
before the next WFI) and makes the todo-5 (c) INTC.PENDING==0 assertion
deterministic: the FM harness sets INTC.PENDING bit 8 on every
host_write_command (doorbell IRQ model), and the firmware previously ACKed
it only after HOST_HEAD — the test's sample point (HOST_HEAD==1020) raced
the epilogue. ENABLE gating + WFI wakeup logic is otherwise untouched.
