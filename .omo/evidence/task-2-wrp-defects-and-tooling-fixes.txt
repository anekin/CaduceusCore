G. BOUNDARY / RESIDUAL STATEMENTS (also written into the RTL header + WRP1-IRQ-RESIDUAL marker)
══════════════════════════════════════════════════════════════════════════════════════════════
  1. DRAIN LATENCY.  Measured in this TB: consecutive store-out bursts are 60 ns apart at a 10 ns
     clock => ≈6 cycles/row (RED log rows 0..10 at 2240/2300/.../2840 ns; GREEN rows up to 0x43f00
     at 6020 ns).  FM-SOC mixed-mode figure ≈11-15 cycles/row is taken from the plan's analysis
     (not re-measured here).  Both are far below the FIFO depth-equality assumption.
  2. WDT TRIP DURING STORE-OUT.  wdt_fire && so_axi_wait forces so_state<=SO_IDLE and DROPS the
     in-flight row (mxu_soc_wrapper.v:714 pre-edit / :784 post-edit region).  The abandoned rows
     are never popped, so so_fifo_empty stays low and DONE stays DEASSERTED — the sticky
     WRP_STATUS[1] is the authoritative indicator for that fault path.  The watchdog suite case
     covers only the PRE-LOAD path (it asserts WRP_STATUS[1] with LOAD_DONE=0 and never enters
     store-out), so this boundary is documented, not covered.
  3. IRQ.  NOT CHANGED.  WRP1-IRQ-RESIDUAL marker at rtl/wrapper/mxu_soc_wrapper.v:390-399 states:
     mxu_irq is a one-cycle pulse (controller.v:145 default clear vs :319 set), a naive
     `mxu_irq && so_drain_done` gate would swallow it forever, any future gate must latch
     mxu_irq_seen and ship with an IRQ_EN=1 test case, and no test currently covers an IRQ_EN=1
     completion (the suite writes IRQ_EN=0).  Todo 6 mirrors this in the ledger.
  4. so_overflow TRIPWIRE.  Recorded as a future item (header :73-75): "wr_ptr == rd_ptr while a
     capture is still in flight" would turn the pointer-equality assumption into a checked
     condition.  Deliberately NOT implemented in this wave.
