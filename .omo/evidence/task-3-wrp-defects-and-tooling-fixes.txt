E. CAPACITY BOUND WRITTEN INTO THE RTL (K <= 128 per command)
════════════════════════════════════════════════════════════════════════════════════════
  The internal buffers hold exactly 2 K-tiles:
    weight_buf[W_BUF_DEPTH=64]     : 1 K-tile = WEIGHT_BEATS_PER_K = 32 entries → tiles 0,1 fit
    activation_buf[A_BUF_DEPTH=128]: 1 K-tile = ACT_BEATS_PER_K    = 64 entries → tiles 0,1 fit
    write indexes weight_buf[(pl_k_tile_cnt*32)+pl_beat_cnt] / activation_buf[(pl_k_tile_cnt*64)+pl_beat_cnt]
    read  indexes act_buf_idx = burst_cnt*64 + data_cycle, w_buf_idx = burst_cnt*32 + data_cycle[13:1]
    (burst_cnt increments once per compute burst == per K-tile) → both leave the arrays at index >= 2.
  ⇒ WRP_K_TILES is honored exactly for K <= 128 (ceil(K/64) <= 2).  K > 128 per command stays
    UNSUPPORTED (out-of-range reads yield X).  Buffer depths are deliberately NOT changed (out of scope).
