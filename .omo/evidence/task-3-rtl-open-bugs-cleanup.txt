1. WHAT WAS IMPLEMENTED (WDT-IMPL)
--------------------------------------------------------------------------------
File: rtl/wrapper/mxu_soc_wrapper.v (+84 net lines, all additive)

(a) Threshold: `localparam [19:0] WDT_TIMEOUT = 20'd1_000_000;` — fixed in RTL,
    NO new MMIO register, not software-configurable. Justified in the file
    header with the existing cocotb budget formula
    (sim/cocotb_bridge.py:_estimate_timeout, lines 2370-2390):
        MMUL: max(50000, M*N*K//64 + 20000)
    for the largest shape in that suite (M=1, K=N=2048):
        1*2048*2048//64 + 20000 = 85,536 cycles  ->  1e6 leaves >10x headroom.

(b) COUNTER RULE (the exact condition implemented):
      wdt_cnt advances on every cycle in which
        (pl_state == PL_LOAD_W_AR) || (pl_state == PL_LOAD_W_R) ||
        (pl_state == PL_LOAD_A_AR) || (pl_state == PL_LOAD_A_R) ||
        (so_state == SO_RD_SCALE_AR) || (so_state == SO_RD_SCALE_R) ||
        (so_state == SO_WRITE_AW)    || (so_state == SO_WRITE_W)
      and is CLEARED to 0 in every other cycle.
    Those eight states are exactly the states whose only exit is an AXI
    handshake (arready / rvalid / awready / wready).  Every other state -
    PL_IDLE, PL_READY, SO_IDLE, SO_TRANSFORM - is "the FSM made progress" and
    clears the counter, so a long but healthy transaction can never accumulate
    to the threshold.  Equivalence note: those eight states are also exactly the
    states that assert m_axi_arvalid / m_axi_rready / m_axi_awvalid /
    m_axi_wvalid, and no other state asserts any of them (verified against the
    four continuous assigns in the same file), so the rule can equivalently be
    read as "count while the wrapper is presenting an AXI request and waiting
    for its response".  Counter saturates at WDT_TIMEOUT-1 (no wrap), so
    wdt_fire is a clean one-cycle pulse.

(c) On trip (wdt_fire):
      * wrp_wdt_timeout <= 1'b1   (sticky, single driver)
      * the offending FSM is forced back to IDLE - surgically, only when it is
        actually in a waiting state:
            PL block: `else if (wdt_fire && pl_axi_wait) pl_state <= PL_IDLE;`
            SO block: `else if (wdt_fire && so_axi_wait) so_state <= SO_IDLE;`
        (surgical gating matters: a blanket reset would also clobber PL_READY
        and therefore destroy a legitimately-set LOAD_DONE when only the
        store-out FSM is stuck).  Forcing IDLE drops m_axi_arvalid / awvalid /
        wvalid combinationally, which is what releases the AXI wait.
      * irq: mxu_top's own interrupt is now `.irq(mxu_irq)` and
            `assign irq = mxu_irq | wrp_wdt_timeout;`
        so the trip is ORed into the shared MXU INTC bit0 line.  The INTC was
        not touched (rtl/intc/** untouched; caduceus_soc_top.v untouched).

(d) WRP_STATUS readback is now `{30'd0, wrp_wdt_timeout, wrp_load_done}`:
    bit0 = LOAD_DONE, bit1 = WDT_TIMEOUT (sticky).  Header register table
    updated for both 0x3C and 0x40, with the threshold rationale added as a
    new header paragraph.

(e) STICKY CLEAR RULE: ANY write to WRP_CMD clears wrp_wdt_timeout, whatever
    the data - bit0=0 included.  Rationale (documented in the RTL comment):
    clearing only on bit0=1 would make the software ack itself re-arm a
    pre-load, because wrp_trigger is `wrp_cs && pwrite && penable &&
    (paddr == OFF_WRP_CMD) && pwdata[0]`.  Writes to any OTHER wrapper register
    (including WRP_STATUS) do not clear it.  If a CMD write and a trip land in
    the same cycle the write wins (the FSM recovery still happens).

FSM-IDLE OBSERVABLE USED BY THE TEST (the task asked which one):
    * PRIMARY (hard assert): `dut.u_dut.pl_state.value.integer == 0` - the real
      wrapper pre-load FSM state, reached through the VPI hierarchy.  Proved
      reachable in the RED run itself: the same probe read pl_state == 1
      (PL_LOAD_W_AR) before the threshold.
    * SECONDARY (hard assert): `dut.m_axi_arvalid.value.integer == 0` - a real
      AXI-side observable, "no outstanding request", independent of internals.
    * NOTE: the mechanism the 5 existing tests use for "IDLE" is
      `dut.dbg_state`, which is mxu_top's CONTROLLER state, not the wrapper
      FSM state; it is asserted too (==0) but it is IDLE throughout this test
      and therefore carries no information.  That is why the two observables
      above are the load-bearing ones.
