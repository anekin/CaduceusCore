1) New storage + reset:
     reg [31:0] last_status_reg;
     reg [31:0] completion_status_reg [0:15];
     integer i;                       // reset-loop index for the array
   Reset branch zeroes last_status_reg and all 16 array entries.

2) Decode:
     wire [4:0] word_idx;
     assign word_idx   = paddr[6:2];
     assign addr_valid = (paddr[11:7] == 5'd0) && (word_idx <= 5'd20);
   → valid window 0x00-0x50 (21 words: 4 pointers + LAST_STATUS@0x10 +
     16 array slots @0x14-0x50).  0x54+ → addr_valid=0 (silent-0).
   reg_sel (paddr[3:2]) is retained + assigned but NOT used by the decode
   (comment states this) — it cannot address the extended window because it
   wraps at word 4.

3) Write path re-keyed on word_idx (NOT reg_sel — reg_sel would alias words
   5..8 onto NPU_HEAD/HOST_HEAD/NPU_TAIL/HOST_TAIL and corrupt doorbell_irq):
     case (word_idx)
       5'd0..5'd3  → host_tail_reg / npu_head_reg / host_head_reg / npu_tail_reg
       5'd4        → last_status_reg
       5'd5..5'd20 → completion_status_reg[word_idx - 5'd5]
       default: ;
     endcase

4) Read mux re-keyed on word_idx, WITH the 0-3 pointer mapping included
   (same order as the write path — omitting it would break pointer reads and
   Test 1-11 / firmware polling):
     word 0 → host_tail_reg, 1 → npu_head_reg, 2 → host_head_reg,
     3 → npu_tail_reg, 4 → last_status_reg,
     5..20 → completion_status_reg[word_idx - 5'd5],
     word 21-31 / out of window → 32'd0

5) ZERO-TOUCH confirmed by diff inspection: bkdoor_we/bkdoor_sel/bkdoor_rdata
   path, doorbell_irq (host_tail_reg != npu_head_reg), pready (psel&&penable),
   pslverr (1'b0) — all byte-identical to HEAD.

6) Header register table updated: 0x10 LAST_STATUS (RW), 0x14-0x50
   COMPLETION_STATUS[16] (RW), 0x54+ unmapped (read 0 / write ignored).
