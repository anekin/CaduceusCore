# Harness vs Loop vs Graph：三层架构工程对比指南 — 调研报告

> **来源**: 无糖AI / beamnxw 长文, 2026-07-27
> **关联**: Hermes 架构分层、快慢双环、Graph Engineering

---

## 30 秒答案

| 层 | 做什么 | 一句话 |
|---|---|---|
| **Harness** | 构建模型周围的运行机器 | 环境 |
| **Loop** | 设计「执行—反馈」往复循环 | 反馈 |
| **Graph** | 让工作流拓扑结构显式化 | 流程 |

串联：**环境 → 反馈 → 流程**

---

## Harness Engineering：模型周围的机器

Agent = 模型 + harness。把模型从架构图里拿掉，剩下全是 harness：

| 子系统 | 内容 |
|---|---|
| 上下文注入 | 指令、检索事实、对话状态、技能、任务策略 |
| 行动接口 | API、浏览器、shell、代码解释器、MCP 工具 |
| 持久化 | 文件、检查点、会话、进度日志、git 历史、长期记忆 |
| 执行控制 | 超时、重试、预算、模型路由、子 Agent 派生、审批关卡 |
| 安全治理 | 权限、隔离、白名单、密钥管理、人工授权 |
| 可观测性 | 追踪记录、工具 I/O、状态转移、成本、延迟 |

**核心观点**：两个团队用同一个模型，结果天差地别——不是模型智能不同，是工作条件不同。

---

## Loop Engineering：基于证据的循环

循环七要素：触发条件 → 目标 → 状态与记忆 → 行动策略 → 证据 → 反馈 → 停止规则

**核心原则**：「不要基于信心来循环，要基于证据来循环。」"Agent 自己说完成了"不是停止条件；测试通过、schema 校验通过、审核批准才是。

三种循环模式：
- **验证循环**：生成产出→确定性检查→证据显示错误才重试
- **事件驱动循环**：定时/webhook/新数据到达时唤醒
- **改进循环**：分析轨迹→修改指令/工具→测试新版本

---

## Graph Engineering：拓扑结构显式化

节点=步骤，边=允许路径（顺序/条件/并行扇出/汇合/循环/人工中断）。状态在图中流转，拓扑可被校验。本质是把 Agent 工作流构建为有向图或状态机。

## 对 Hermes 的映射

| 层 | Hermes 实现 |
|---|---|
| Harness | Memory/Skills/Tools/Cron/Session/error_db — 基本完整 |
| Loop | 快慢双环（error_db 匹配 + 系统化调试） |
| Graph | delegate_task + structured-execution，缺 Verifier/条件路由/人工审批节点 |

最应该加强的：**Harness 层的持久化子系统和安全治理。** 当前 Hermes 的进度恢复、权限分级、审计追踪都是隐式的——代码中有但未形式化。
