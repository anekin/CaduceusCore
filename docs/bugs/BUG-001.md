# BUG-001: exp LUT 默认 entries=256 导致 Func Model 线性插值误差超标

## Bug ID

BUG-001

## Title

exp LUT 默认 entries=256 导致 Func Model 线性插值误差超标，不满足 testplan 验收标准 (max_error < 1e-5)

## Severity

Medium

## Module

`GoldenSFU._build_exp_lut` (`sim/golden_executor.py`)

## Status

**FIXED**

## Discovered by

SF-02 test case

## Discovered date

2026-06-29

## Description

`_build_exp_lut(entries=256)` 默认值从 RTL ROM 尺寸继承。256 entries 下线性插值误差最高 ~7e-4，远超 testplan 要求的 `max_error < 1e-5`。

RTL 自身的 tolerance (`abs_tol=2e-3`) 是 Func Model 验收标准 (1e-5) 的 200 倍，因此 256 entries 对 RTL 验证足够但对 Func Model 不够。

## Steps to reproduce

1. 调用 `GoldenSFU()._build_exp_lut()`（默认 256 entries）
2. 对 `[-20, 0]` 区间均匀采样 1000 点
3. 计算 `_exp_hw(x)` vs `np.exp(x)` 的最大误差
4. 观察到最大误差约 7.4e-4，超过 1e-5 阈值

## Root cause

Func Model 的默认参数直接复制了 RTL ROM 的 256-entry 尺寸，未考虑 Func Model 自身的精度要求远高于 RTL 验证 tolerance。

## Fix

- 将 Func Model 默认 entries 从 256 改为 4096
- 增加注释说明：
  - RTL 256 entries 配合 `abs_tol=2e-3` 足够
  - Func Model 需要 4096 entries 才能达到 1e-5 的验收标准

## Fix commit

`295d6b9`

## Verification

- SF-02 test: **PASS**
- Golden test suite: **477/477 PASS**

## Lessons learned

- Func Model 参数不应从 RTL 直接继承
- Model 和 RTL 有各自独立的精度需求
- 数值默认值需对齐 Func Model 自身的验收标准，而非 RTL 的 tolerance
